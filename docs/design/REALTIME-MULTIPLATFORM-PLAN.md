# Realtime discovery and durable collection implementation plan

Implementation plan, October 1, 2026. This document defines the target design and acceptance gates. See [implementation verification](REALTIME-VERIFICATION.md) for measured results and remaining work; a plan entry is not evidence that its acceptance gate passed.

Start one local collector, discover participating Android, iOS and browser producers, list their devices or environments, apps and sessions, and retain sanitized captures on the collector machine. Device and package arguments become optional filters. Automatic discovery works within an authorized development environment; it does not instrument arbitrary apps or bypass device authorization, sandboxing or browser isolation.

## Baseline and scope

Before this update, the collector served the viewer on loopback, accepts authenticated HTTP NDJSON batches, fsyncs before ACK, deduplicates stable event IDs, and uses SSE for viewer notifications. Android selects one ADB device and package, writes pairing, and polls whole files every two seconds. Android native and Swift transfer sinks already persist and retry batches. The Swift package transfers sanitized events and is not a complete capture SDK. Browser capture has IndexedDB journals and an explicit upload through a loopback development relay, but no continuous sender or durable delivery cursor.

Use a clean start: one current capture schema (1.2), one source-aware transfer/pairing contract (2), and new collector/source state. Update the collector, Android, Swift, browser SDK, demos and fixtures together. There is no legacy API, source/capture import, cursor conversion, unknown-ownership adoption or old-directory support requirement. Older captures/state are left untouched; startup uses a new state directory and reports unsupported state rather than overwriting it. Logical session grouping, stable retry identities, sanitized capture semantics and production exclusion remain requirements. General iOS network instrumentation, cloud collectors, arbitrary website inspection, mobile OS background jobs and unrestricted physical iPhone filesystem access are outside scope.

The UI calls the top level **Devices and environments**. A browser environment is an origin-scoped, random local ID, not a verified physical device or browser profile fingerprint. Native app identifiers are actual application IDs or bundle IDs. Web apps use an explicitly configured app ID plus frontend origin. Do not infer a mobile browser's hardware identity from its IP or user agent.

## Shared architecture and identities

Implement concrete Android and simulator discovery loops sharing only cancellation, bounded concurrency and reconnect/backoff helpers. Local loops discover sources and pass validated provenance and sanitized events to ingestion; native senders and web relays register and push directly. Each source is isolated from failures in other sources. No plugin framework, generalized transport router or scheduler is needed.

## Developer workflow

`npm start` starts the collector, opens its ordinary viewer URL and discovers all available authorized Android devices and booted iOS simulators. Device/package options are optional inclusion filters. The sample build/install command remains a separate convenience. Missing ADB/Xcode, unauthorized devices, absent descriptors and unpaired apps become actionable adapter/source statuses; they do not block the viewer or other adapters. Proposed defaults are `<checkout>/artifacts/collector-v2` for data and `<homedir>/.http-sequence-logger/active.json` for the private active manifest.

Publish the active manifest only when no live owner exists. A second collector cannot steal it or existing pairing; it requires explicit directory/port and runs without activation. A relay uses its explicit private manifest override when configured, otherwise the active manifest. Same-identity endpoint refresh is automatic; selecting another collector requires deliberate selection and fresh authorized enrollment. A stale manifest is repaired only after ownership/liveness checks; unsafe ownership/type/permission failures are diagnosed. No project routing service, daemon manager or port scanning is required.

Debug bootstrap helpers own the installation ID, descriptor publication, pairing refresh, one connection manager and status. Android uses a documented `getNoBackupFilesDir()/HTTPSequenceLogger/source.json` convention; iOS uses the Application Support convention below with backup exclusion. Hosts wire their existing capture hooks and sanitization; iOS instrumentation stays app-owned. Publish one minimal external-consumer recipe for Android, Swift and web, including custom debug suffix/configuration and production isolation. Bootstrap creates the descriptor while the collector is absent, so later discovery works.

Always mount the relay when the frontend's debug integration is enabled. Missing collector configuration produces a bounded waiting response, and the frontend/journal continue working. Start frontend before collector, restart collector without restarting frontend, and connect devices later as normal supported workflows. A page registration makes the web app visible; an empty dev server appears only in adapter diagnostics.

Use one primary collection status with a short reason and next action: Ready and waiting for events, Delivering, Backlog retained, Permission required, Tool unavailable, Another collector selected, Storage full, or Last seen with retained history. Details expose delivery and persistence counters without identity machinery dominating the UI. Default navigation is Devices and environments → Apps → Sessions; installation/journal/process distinctions are labels/details unless ambiguity requires an extra group. Viewer pause explicitly says collection continues.

Add read-only `collector status` and `collector doctor` CLI subcommands using the same status model. Show selected collector/directory/endpoint, tool/runtime versions, storage ownership/free space, adapter health and backlog without secrets. Diagnose and suggest repairs; do not mutate pairing or delete state. Update cli.mjs, runtime.mjs, scripts/android-live.mjs and web-sample/vite.config.mjs explicitly; remove SAMPLE_PACKAGE-based default discovery.

## Source identity

Persist these identities:

- Environment: collector-local device identity with platform tool aliases, or a browser's origin-scoped ID. LAN native environments initially remain installation-scoped unless a trusted provisioning step links them. Names and IP addresses are labels, not keys.
- App: platform and actual package/bundle ID, or configured web app ID and exact origin, scoped to environment and Android user/profile where supported.
- Installation: random ID in development-only state excluded from device backup, or browser origin storage. Validate new/restore/reset behavior rather than assuming reinstall clears private state. Do not use hardware advertising identifiers.
- Source: collector-issued ID bound to a paired principal and installation or browser journal. Source identity does not change when the delivery connection reconnects.
- Process/page instance: ephemeral ID used for presence and distinguishing concurrent producers. Browser pages use separate writer journals; reload may resume a retained journal after acquiring transactional exclusive ownership. No global browser leader-election service is needed.
- Recording and session: preserve existing recording_id and (session_namespace, session_id). One logical session may include recordings from multiple sources. The device/app tree is a filter over that session.

ADB/simulator provisioning can bind a local descriptor to the source credential issued for that package/container. Direct LAN registrations carry installation-scoped asserted labels, not independently attested device/package identity. Never automatically merge environments by matching names, IPs or app IDs. Both push and file retrieval for an installation must resolve to the same source before ingestion, or remain visibly unlinked rather than silently merging.

After a local adapter enrolls a new installation, establish its trusted local environment binding and verify the returned source identity before caching the connection or publishing pairing credentials. The first clone reconciliation must be rejected without requiring an original-device watcher restart. Possession of a copied bearer credential still grants its original source authority; local alias validation is not physical-device attestation.

Implement these concepts around one canonical source record, not separate CRUD subsystems for each identity. Native sources represent installations; browser sources represent journals within an installation. Device/environment and app nodes are query projections. The minimum storage model is sources and scoped credentials, ephemeral presence, recordings with source ownership, original events with unique ID/sequence indexes, file follower checkpoints, and recoverable enrollment operations. Session summaries derive from indexed recordings/events and preserve existing session keys.

Use Android getNoBackupFilesDir or targeted debug-only backup exclusions for installation, descriptor and credential state without modifying the host app's business backup policy. Exclude equivalent iOS debug identity/pairing/journal state from backup and reconcile restored/cloned descriptors. Do not rely on iOS Keychain uninstall persistence as an installation boundary. Test restore to another device, reinstall, data reset and simulator erase; invalidate mismatched identity/credential/checkpoint state without deleting canonical captures.

Source metadata is transport provenance, not a mutation of original capture events. Every collected recording has an authenticated source owner from its first ingestion; reject missing or conflicting attribution. Push and file replay from that owner deduplicate identically in either arrival order. Known ownership cannot be relabeled through metadata or upload claims. Export the current NDJSON format; add a metadata manifest only when an export must preserve environment/app associations. Offline viewer import is separate from source registration and does not adopt imported records into collector history.

## Registration and transfer contract

Define one source-aware registration, ingestion and pairing contract over HTTP. Use transfer version 2 across all producers, relays and viewer routes; capture schema version 1.2 remains independently identified. Remove old routes/ACK/config parsers and regenerate current-format fixtures instead of maintaining compatibility branches.

Proposed routes, to be specified precisely before implementation:

- POST /api/v2/register: a provisioned enrollment credential registers bounded installation/app metadata and capabilities. The collector issues a source ID and source-scoped upload credential. Registration requires authentication and is idempotent for the authenticated installation identity.
- POST /api/v2/presence: source credential updates process/page presence and bounded delivery status. This does not create synthetic capture events or imply successful business operations.
- POST /api/v2/events: source credential identifies provenance; body remains complete NDJSON lines, at most 1 MiB and 500 events. Preserve atomic batch validation, conflicts, deduplication and the 2 MiB ACK bound. ACK echoes source and collector identities and submitted event IDs.
- Loopback viewer GET routes under /api/v2: environments/apps, sources, paginated session summaries, selected session events and export. Preserve separate reader authority and strict same-origin bootstrap; refresh its contract with the viewer rather than retaining old routes.

No source ID in the body or a header grants authority by itself. Native credentials stay in private debug storage; browser collector credentials stay exclusively in Node. Browser registrations obtain only bounded relay-local handles; the relay binds those handles to its configured app, exact origin, journal generation and authorized frontend session, where remote access is enabled, and adds collector authentication itself. Handle possession is not app attestation; same-origin application code is within the trusted frontend boundary. Host/Origin checks constrain browser requests but do not authenticate arbitrary LAN clients. A reachable relay requires a documented access middleware boundary covering registration, presence and uploads, plus session binding and CSRF protection; test non-browser clients supplying the correct headers without authorization.

Provision enrollment tickets through the trusted local collector UI or local tool. Proposed defaults are 256-bit random tickets, 10-minute expiry, collector/principal binding, and a single native installation or explicitly bounded relay journal scope. Persist a registration operation ID before the first request and bind it to the enrollment principal and metadata fingerprint. Atomically commit ticket consumption, source identity and a privately retained recoverable result. Identical retries return the same source and credential through the ticket's recovery window; conflicting reuse fails. Expired recovery requires explicit new provisioning that preserves the authorized source identity. Installation IDs never select another principal's source. Source credentials have upload and own-presence authority only; retain them privately, support explicit revoke/rotate, and keep renewal on the same source ID. A proposed rotation overlap of 60 seconds is bounded and does not apply to immediate revocation. Revocation blocks automatic re-enrollment and retains canonical backlog. Collector read access is a separate credential role.

Native delivery cursors, like browser cursors, bind to collector ID, source ID and journal/file generation. Create new-format state directly; do not interpret old cursors. A deliberate collector/source change resets the delivery cursor for retained canonical history. ACK never removes canonical records. Reusing the same collector ID alone cannot authorize a different source's delivery state.

Keep small HTTP batches and an authenticated Fetch SSE stream. Notifications carry {collector_id, event_cursor, registry_revision} as authoritative hints. Events use a durable collector-global ingestion cursor, independent of source timestamps. Registry changes use a separate revision so a device can appear without an event arriving. Register the subscriber before emitting ready, fetch snapshots after subscription, and reconcile newer buffered hints. Snapshot responses include committed watermarks; registry pagination binds to a revision and restarts on invalidation. Event pages pin a high-water boundary and return next_after even when filtered results are empty. Replace collector-client.mjs pagination assumptions directly. Coalesce notifications and retain bounded stream backpressure.

## Pairing and discovery

Local adapters and Node relays read a private collector manifest in a documented per-user runtime location, with explicit file overrides. The manifest identifies the configured active collector; multiple collectors require explicit selection. No port scanning and no silent choice of a different collector. Use an owner-only directory and bounded regular-file reads; verify ownership/type/permissions, reject unsafe symlinks, validate the fixed endpoint, and keep it outside frontend static roots. Publish atomically and include collector instance/generation and pairing owner. Shutdown removes a publication only if it still belongs to that instance. Revalidate identity before refresh; never send old credentials to a newly selected collector or follow redirects. Read credentials never enter that manifest for producers.

Android discovery starts with all ADB devices. A fixed source descriptor appears once initialized. Probe descriptor presence in bounded remote batches through cached package enumeration and debuggable private-file access; validate full descriptors individually and reprobe every scan so initialization after an earlier miss is detected; do not inspect old capture locations. A debug-only static marker may optimize this only if a bounded package metadata query is proven on supported devices. Do not add an exported provisioning service just for discovery. Invalidate caches on package changes and do not create directories merely to test eligibility. Initially support the validated default user; enumeration, descriptor reads, pairing and capture retrieval must use the same numeric profile. List inaccessible profiles as unsupported and enable them only after real-device validation. Reverse routes are shared per device/collector port and pairing is per installation. Restore only collector-managed pairing after reconnect; respect explicit app selection and a different collector's ownership.

Schedule the next Android sweep one second after the current bounded sweep completes; keep four workers, descriptor batches of at most 32 and a ten-second enumeration cache. Sweeps never overlap. A measured 655-candidate sweep plus the previous two-second idle period left newly initialized installations above the proposed five-second target. Reducing idle time increases ADB polling (approximately 35% at the recorded scan cost); it does not guarantee the target for arbitrary device counts, slow tools or candidate inventories. Record both the earlier overrun and any post-change measurement.

Simulator discovery uses simctl-resolved containers rather than hardcoded UUID paths. Xcode 26.2 read-only review found listapps and get_app_container reject a shutdown simulator with SimError 405; iterate explicit booted UDIDs and never use the ambiguous booted selector when multiple simulators exist. Parse listapps output as a property list, not assumed JSON. Use a fixed Library/Application Support/HTTPSequenceLogger/source.json descriptor, with bounded canonical relative paths inside that container. Validate real containment and safe opened file types for descriptor, captures and pairing writes; reject absolute paths, traversal, symlink escapes and replaced-container identities. Bound paths and read work. Update the demo to the new convention directly. Write collector-owned `pairing-local.json` atomically; the app owns explicit `pairing.json` and prioritizes it on foreground/reconnect. Local provisioning cannot overwrite an explicit app selection. The canonical journal stays open while delivery credentials/connection are replaced.

Update the iOS manual demo to append sanitized events incrementally to the new journal; its current end-of-session file write cannot demonstrate live recovery. The Swift transfer package gains a journal writer and sender that tails durable lines. This remains storage/transfer support, not automatic network instrumentation. Replace Android's current truncating/unpaired and fsync-per-event writer paths with the same canonical-journal lifecycle. Use the execution model below rather than asking integrators to keep capture work off the UI thread themselves.

## Execution and producer journals

| Owner | Responsibilities and boundaries |
| --- | --- |
| Collector Node event loop | HTTP framing, bounded body admission, SSE, async filesystem/device commands and worker replies. No SQLite calls or file fsync here. ADB/simctl subprocesses have timeout/cancellation and output limits. |
| One collector database worker | One SQLite connection owns writes, registration, credential checks, quotas, attribution, deduplication, ingestion watermarks, file checkpoints, queries and passive checkpoints. Each bounded batch gets one short atomic transaction. No transaction waits for network/device/socket work. |
| Native capture admission | Assign IDs, per-recording sequence and monotonic observation order and snapshot sanitized immutable data under one short recording lock/owner. Enqueue in that same order. No serialization/fsync/network inside the recording lock or UI callback. |
| Native serial file owner | One bounded disk queue owns serialization, append, rotation, durable watermark and cursor/config publication per installation journal. Android uses a dedicated executor; Swift uses a serial file-I/O queue behind async calls, not a detached task per event. |
| Sender per journal | One active drain and retry timer read only durable bounded batches. HTTP awaits run outside disk critical sections. ACK cursor updates return to the file owner and are fenced by connection generation. |
| Browser journal owner | One transactional owner token and increasing epoch per journal; all append, accounting, ACK and release mutations check both inside IndexedDB. Concurrent tabs use separate journals. A stale suspended owner cannot mutate a journal taken over by another page. |
| Viewer | One catch-up task coalesces the highest event/registry watermark. Source/session selection, pause/resume and collector changes increment a request generation; abort old requests and discard stale replies after every await. |

For native producers keep one append-only canonical journal plus small delivery cursors, with no second persisted upload spool and no dual-write handoff. Trigger a grouped flush when the oldest queued item reaches 50 ms, a group reaches 64 KiB, or 500 events arrive; one allowed large event may exceed 64 KiB up to 1 MiB. These are batching triggers, not disk-completion deadlines: scheduling/fsync may take longer, bounded queues reject further admission, and the async durability barrier reports completion/error. Uploads still cap at 1 MiB/500 events. Keep file handles open; avoid opening/fsyncing or hashing the whole acknowledged prefix for every event.

Logging-hook enqueue means accepted into bounded memory, not durable. An explicit async `flush()` barrier waits for actual persistence through the admitted position captured when it was called; it does not wait for future appends or successful upload. Queued/unflushed events may be lost on abrupt process death. Queue/full-journal rejection increments drop diagnostics without blocking/changing business requests. If a caller requires persistence before return, expose an explicit worker/async durable operation. Serialize terminal event admission and graceful close with prior accepted appends; reject later appends, persist the admitted prefix, cancel delivery and report retained backlog. Never release a writer lock while its disk jobs still run. A partial append/sync failure blocks that writer until checked/reopened. Reopen retains and validates complete lines, repairs only an incomplete final tail, then resyncs and republishes; never truncate complete bytes merely to match a stale published watermark.

Rebinding leaves canonical capture running: serialize the transition, increment connection generation, cancel old timer/upload, await sender shutdown, and install new credentials/cursor scope. Late sender completions check that generation before updating delivery cursor/status/timers. Canonical append, flush barriers and rotation are fenced by journal ownership and continue across connection changes; they must not be discarded by a sender-generation check. Cancellation cannot prove a request did not commit; replay handles ambiguous outcomes. Timeout shuts down networking/device work, but cannot force-cancel fsync; retain the writer lock until disk work ends or the process exits, and report a stalled writer.

Rotate into unique append-only journal generations with explicit byte/file-count budgets. Seal at complete-line boundaries and retain after ACK. Sender reads use the file owner's immediate in-memory synced position. Active local-pull generations publish a generation/boundary watermark after data sync, coalesced on a proposed 250 ms or 1 MiB durable advancement and forced on seal/graceful close. These publication triggers can also be delayed by disk work. Native local publication uses generation equal to journal_id and the enumerated directory name; adapters reject missing/mismatched generation controls without advancing checkpoints. Followers stop at the published boundary. After a crash, conservative stopped-app recovery may omit an unpublished synced tail until producer reopen validates/resyncs/republishes it; process absence or visible complete lines alone is not a durability proof. Each concurrent native process has a unique journal/writer lock; installation-scoped source cursors/checkpoints include journal ID. The fixed descriptor names a bounded journal directory with per-journal metadata, avoiding a shared mutable file list. Initialize shared installation state with exclusive creation/locking. Pairing/descriptors/manifest/cursors use bounded temp write, file sync, atomic rename and directory sync where supported by the failure model. Cursor loss replays; enrollment/config loss recovers idempotently. Rename alone is not a power-loss guarantee.

An atomic publication succeeds only after its required parent-directory open and sync succeed. Constructor failures close opened handles before releasing ownership. On journal reopen, acquire the writer lock before removing exactly recognized abandoned metadata/cursor temporary files; preserve unrelated and nonregular paths. A fixed temporary path must reject symlinks/nonregular files before truncation. Test repeated process interruptions after temporary-file write, temporary-file sync, rename and directory sync, and verify retained records, scoped cursor replay and bounded temporary-file growth. These are process-crash boundaries between operations; they do not establish interruption inside an OS syscall or power-loss durability.

Bound native and collector queues by both jobs and bytes. Proposed starting admission budgets are 4 MiB per native writer, one pending follower batch per source, 16 MiB aggregate collector event buffers/jobs and 2 MiB per source, plus reserved bounded control/query capacity. Reserve capacity before reading request bodies and release it on every failure path. Rotate ready source jobs fairly; do not let a backfill monopolize the worker. Coalesce presence. Respond to overload with retryable status and Retry-After; uncertain worker failures never produce success ACKs. Tune budgets under representative event sizes instead of adding a general group-commit scheduler.

LAN mode is explicit. Advertise a proposed DNS-SD service such as _nlog._tcp containing non-secret service/version/collector identifiers. Select and trust a collector once using existing connection JSON or a QR representation that carries endpoint, pin and a short-lived enrollment credential. mDNS only suggests candidates; it cannot establish a trusted certificate pin or grant upload credentials. Prefer a stable paired endpoint hostname, collector identity and pin; discovery may refresh addresses without replacing the trusted TLS reference name. IP-based pairings require repair when the address changes. Reconnect automatically to the already paired collector. Multiple candidates, changed identity/pin, expired certificates or denied permission remain visible and require deliberate repair. Manual pairing remains available when multicast is blocked. Validate IPv4/IPv6, name collisions and address changes.

Browse on native apps through platform APIs; do not invent UDP discovery for browser JavaScript. Put NSBonjourServices for the selected service type and NSLocalNetworkUsageDescription in the iOS debug target. Start first-time browsing/enrollment while foregrounded; background requests with undetermined permission can be silently denied. The simulator does not model local-network privacy, so permission gates require physical-device evidence. Use platform Bonjour APIs; do not assume a raw multicast entitlement is necessary for ordinary Bonjour browsing. Validate desktop advertisement under both Terminal launch and the actual application/helper launch context on macOS. Android LAN permission behavior must be tested by OS and target SDK, including Android 16 opt-in and target SDK 37 enforcement.

## Browser continuous capture

Replace web-sdk/src/storage.mjs whole-history memory hydration with metadata-first open and indexed bounded range reads. Persist small bounded append groups, accounting and owner epoch in short IndexedDB transactions; notify the sender only on completion. Keep an ACK cursor scoped to collector, source and journal generation. Reload recovery acquires a fresh owner epoch only for a released journal or one eligible after stale liveness, checked transactionally; it must not take over a healthy active page's journal. Concurrent active pages create fresh journals. Every later mutation is fenced, so an apparently stale owner waking later cannot overwrite recovered state. Any lease is only a liveness hint. Browser strict durability is a hint, not a universal power-loss promise. Never await Fetch/timers inside a live IndexedDB transaction.

Add startJournalDelivery(journal, options) to the debug entry only. Trigger on persisted appends, flush within a proposed 250 ms while foregrounded, and use one drain promise, a dirty flag and one capped-backoff retry timer. Recheck persisted high-water after clearing the drain flag to avoid a missed append at drain completion. Read a bounded batch and close its transaction, upload using uninstrumented Fetch, then verify every ACK identity/event ID in a new fenced cursor transaction. A lost response/cursor commit replays stable IDs. Retain canonical records after ACK, with explicit capacity/export/rotation and drops.

Extend the always-mounted debug Node relay with registration, presence and current event routes. Refresh the private manifest safely rather than requiring a dev-server restart. With no collector, the development server/journal still work and delivery reports waiting. A page's journal registration lists the app before any events; relay availability belongs in adapter diagnostics, without a standalone relay source/presence lifecycle.

Use uninstrumented Fetch; dispose senders when the journal closes. Pause timers/connection attempts for suspended pages where observable, resume on visibility/online events, and treat these as hints rather than proof of reachability. Do not depend on unload, sendBeacon, service workers or Background Sync for lossless delivery. IndexedDB denial, eviction and abrupt process loss remain browser limitations; expose persistence errors and keep memory export available. No browser-to-collector CORS exception or global token is introduced.

## Durable collector storage and viewer

Use one authoritative SQLite store in the database worker, with a pinned supported Node runtime and one SQLite implementation. Keeping the old Node minimum is not a compatibility requirement. Verify packaging and actual sqlite_version(); require SQLite 3.51.3+ or a documented fixed backport containing the WAL-reset fix. Use a local filesystem, WAL and synchronous=FULL; verify settings and macOS fullfsync behavior against the stated failure model. Events, source ownership, accounting, ingestion position and applicable follower checkpoint commit together before ACK, then notify. Source authorization/revocation and ownership checks serialize with these writes. Duplicate-only batches remain acknowledgeable at logical event capacity.

For export capture immutable event high-water H, then keyset-page retained events at ingest_position <= H using short read transactions. Release each transaction before socket/file awaits and interleave pages with writes. Snapshot the optional source metadata manifest once. Bound export concurrency/duration/output buffers and honor HTTP backpressure/cancellation. This preserves an append-only event snapshot without an HTTP-long SQLite read transaction pinning WAL.

Keep one collector owner per directory. Initialize a fresh database and fresh enrollment/source state; no existing capture.ndjson or source state is imported. Use a new default directory and leave old artifacts untouched. Incompatible database/config versions produce an actionable error asking for a new directory; no data conversion or automatic deletion is required for this release. Keep NDJSON as export instead of a second authoritative mutable journal. Back up current-format credentials/state without printing secrets.

Follower checkpoints bind to source/generation, file identity, durable position and bounded boundary samples; advance only through committed complete lines. Read from offsets in at most 64 KiB chunks with one pending 1 MiB/500-event batch per source. Hash newly read bytes incrementally, not whole historical prefixes. Replacement/truncation/boundary mismatch replays a generation from zero. The append-only convention does not promise detection of arbitrary edits inside already skipped history. Handle incomplete UTF-8/newline tails and rotation; missing unretrieved generations produce a visible gap. Ensure ADB performs bounded reads on the device, not a full cat buffered and sliced on the host.

Storage has configurable global/per-source quotas; the initial policy rejects new event writes at capacity without deleting retained events. Distinguish producer journal/queue limits and capture drops from delivery errors. Storage full, malformed captures, conflict and revoked credentials remain diagnosable. Back off transient failures; storage pressure waits for an actionable capacity change instead of busy-looping; permanent errors block only the affected source. No retention expiry or automatic deletion in the first release. Backup/export and explicit archival are operator choices.

Budget physical DB/index/WAL bytes, export temporary files and backups as well as logical event bytes; enforce a configured free-space reserve before admission. Use SQLite's passive checkpoint initially, monitor progress/WAL growth and throttle new writes if budget is threatened. Do not manually unlink WAL or assume journal_size_limit is a hard active-WAL cap. Use the SQLite online backup API or a safely closed database for backups. Disk-full at append/commit/checkpoint/export yields diagnosable failures, retains unacknowledged producer data and never returns a success ACK for an uncertain commit.

Bound control-plane work as well as event bytes. Proposed initial limits are 16 KiB control JSON/descriptors, bounded depth/string/path lengths, 1,000 retained source records per collector, explicitly limited journals per relay grant, four discovery workers, eight concurrent uploads globally and two per source, and coalesced presence no more than once per second per source. Presence normally updates every 10 seconds with a proposed 30-second last-seen threshold; idle/suspended producer state remains unknown rather than proving disconnect. Apply per-principal admission limits and bounded notification queues. Floods must not prevent a separate source from delivering. Tune these proposed values with representative fixtures.

Build the three-level source sidebar and all-sessions view with the first ingestion slice. Query selected sessions on demand and incrementally update summaries. Preserve intentional sessions spanning sources; filtering hides other source recordings without changing the logical session key. Accepted uploads refresh presence; heartbeat only idle active producers. Show one primary status/reason with expandable details. Presence expiry means last seen/unknown; restart resets live presence. Session completion comes only from capture events, and pausing viewer reads leaves collection running. Keep generation-fenced catch-up and selection from the execution model.

## Validation and success criteria

Protocol/store: lost ACK after commit, process kill before/after commit, partial file tails, fresh initialization interrupted, unsupported-state rejection without mutation, identical replay, ID/sequence conflicts, conflicting source attribution, quota/disk-full and read pagination/notification races. Deduplication survives restart and retained history boundaries; no acknowledged event is silently lost under the documented crash model.

Concurrency and disk gates must use controllable stalls and adversarial ordering, not timing-only happy paths:

- Race native push and local replay of identical events and conflicting ownership/sequence claims; commit one owner and one row per stable ID.
- Slow SQLite commit/checkpoint and slow/disconnected export with other sources active: bounded HTTP/job buffers, responsive health/SSE, fair admission and monitored WAL budget.
- Kill at enqueue, append, sync, durable-prefix publication, SQLite commit, ACK and cursor publication. Distinguish unflushed-tail loss from acknowledged collector durability.
- Rebind/shutdown during a stalled upload, then return its old ACK; cursor/status stay generation-correct and the disk owner retains its lock until jobs finish.
- Concurrent callbacks and terminal close across recordings; sequence/order remain coherent, later admission fails, queue/full-journal drops are explicit.
- Browser owner A suspends, B acquires a new epoch, then A wakes and returns an ACK; all stale mutations fail. Append exactly at drain completion must trigger another drain.
- Large native/browser histories: no per-event whole-prefix hashing, full-file ADB reads or whole-journal IndexedDB hydration. Exercise rotation, partial UTF-8/newline, missing generation, disk full during append/commit/checkpoint/export, and safe cursor-loss replay.
- Rapid viewer filter/selection/pause changes while stale requests and SSE bursts complete; current selection never receives an earlier generation's data.

Developer experience gates include clean startup with no tools/sources, frontend before collector, collector restart without frontend restart, later device connection, two collectors/projects without implicit retargeting, zero-event page registration, custom native debug IDs/configurations and actionable paused/permission/storage/ownership diagnostics. Run external consumer recipes, not only repository samples.

Security: foreign-origin bootstrap/relay access, Host rebinding, unauthenticated LAN clients with spoofed valid headers, cross-session relay handles, spoofed source IDs, registration/presence flood, expired/redeemed enrollment and lost-registration-response recovery, source credential revocation, redirect/token leakage, wrong/expired TLS pins, path traversal/symlink escape, malformed metadata and oversized input. Reject unsafe manifests and verify old-instance shutdown cannot remove newer publication. Credentials cannot enumerate/read other sources. Reject arbitrary relay targets and keep the LAN viewer/read APIs inaccessible.

Platform: collector before/after apps; connect/disconnect devices; package install/reinstall; multiple Android profiles where supported; simulator container replacement; iOS suspend/foreground/kill; browser reload, conflicting writers, closed-tab recovery on next open, private browsing/storage errors and journal rotation. Capture/network business behavior remains functional with discovery unavailable.

Update existing tests, generated examples and integration scripts to the new contract; remove obsolete compatibility assertions instead of retaining branches to satisfy them. Then run npm test, build:viewer, check:live-setup, check:web-types, check:web-browser and check:web-release. Run Android release-isolation checks, Swift package tests, simulator integration and iOS release-isolation checks. Extend shipping-artifact checks to descriptors, discovery/Bonjour configuration, enrollment/source credentials, connection managers and relay access code. Add actual physical device and Safari/Firefox coverage for their increments. Test synthetic discovery with fake adapters, but require real platform evidence for command, permission and lifecycle behavior.

Proposed performance targets are warm-cache initialized-source discovery within 5 seconds and committed foreground events visible within 1 second on an uncongested network. Measure cold package/container enumeration separately with declared candidate count and bounded work; do not hide its cost behind the warm target. Test at least 10 active sources and 1 million retained events without full-history hydration; publish hardware/event-size assumptions, native callback latency, writer queue high-water, collector event-loop lag and DB/WAL size. Capacity tests do not override the realistic selected-session diagram size limit.
