## Reproduction

Run `npm test`, `npm run check:live-setup`, `npm run check:web-types`, `npm run check:web-browser`, `npm run check:web-https`, and `npm run check:web-release`. Capacity scripts are `scripts/check-collector-capacity.mjs` and `scripts/check-web-capacity.mjs`. `npm run check:viewer-realtime` measures installed Chrome visibility. `npm run check:web-storage-denied` exercises actual Firefox denial and memory fallback with the sample fixture servers. `npm run check:native-realtime` measures scoped real emulator/simulator reconciliation and foreground receipt; it requires initialized participating apps and explicitly preserves manual pairing. On macOS, `npm run check:collector-disk-full` creates, exhausts, detaches and removes an owned 64 MiB disk image; it never exhausts the host volume. Generated artifacts under `artifacts/` are local evidence and are not private state to publish. `npm run check:collector-bonjour` tests actual macOS advertisement/discovery/withdrawal with an owned private collector. Its reporting now archives the executed helper, records seven source hashes and inspects only a bounded chain of process executable names and parent IDs, excluding arguments. Observed Apple Terminal ancestry is reported separately from macOS permission attribution. This reporting refinement has not been executed as another DNS-SD check; the independent Terminal gate remains open. `npm run check:native-crash-stages` runs isolated JVM/Swift subprocess milestones using JDK 17 and the Swift toolchain. `npm run check:android-instrumentation -- --device SERIAL` builds and runs isolated current Android fixtures while preserving existing canonical/pairing hashes and reverse routes. Native commands and external consumer recipes are documented in the platform guides.

Before the Android lifecycle check, rebuild the local SDK artifacts from `android/` with `./gradlew :logger:bundleDebugAar :logger-api:jar`; its fixture links these artifacts and records their hashes. `npm run check:native-installation-lifecycle -- --platform android --device SERIAL` uses a uniquely named disposable Android app. The iOS equivalent uses `--platform ios --simulator UDID` and changes only its uniquely named app. `--platform ios --owned-simulator-erase` instead creates, tests, erases and deletes its own simulator, and cannot be combined with an existing simulator target.
